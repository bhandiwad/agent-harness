# Plug in your DataFusion context layer

No DataFusion deployment/API is assumed. The harness currently speaks a small fixed REST adapter contract. Map that contract to your real DataFusion API when it is ready, or inject a Python adapter implementing `invoke(operation, arguments, context)` and `reconcile(operation_id, context)`. This is not Apache DataFusion and does not require changing your context architecture.

1. Copy the object in `config/datafusion-connection.example.json` into `connections` in `config/agent.json`.
2. Replace its HTTPS endpoint with a reviewed adapter endpoint and operation path. Add `datafusion_search` to the agent's `tools`. Align input/output schemas with the agreed response contract. The example schema deliberately requires sources with reference, version and text; add metadata such as freshness or confidence when available, without fabricating it.
3. Add `p, operator, TENANT/WORKSPACE, context:read` to the policy. Map each allowed user's exact IdP subject to a private delegated token file in `subject_token_files`; the worker reads only that subject's token. Mount those files read-only and limit their scopes. Never substitute a broad shared service credential for source authorization.
4. The adapter receives `POST /context/search` with a bearer token and the body below. Identity/scope are generated by the harness, never accepted from model arguments. The destination must independently authorize tenant/workspace/subject and source access.

```json
{"version":1,"operation_id":"UUID","scope":{"tenant_id":"UUID","workspace_id":"UUID","subject":"USER_SUBJECT","task_id":"UUID","plan_revision":1},"arguments":{"query":"Which pumps are associated with asset A17?"}}
```

Return a bounded JSON object such as:

```json
{"sources":[{"reference":"datafusion://assets/A17","version":"v3","text":"Asset A17 has 8 pumps."}]}
```

A success status with an empty `sources` list means no accessible evidence; it is not proof that the requested fact is false. A refusal, timeout or schema mismatch must not be converted into invented sources. Tool results are untrusted data. Preserve permission/error distinctions in your adapter's own response schema when needed. The configured maximum response size is 64 KiB, with a 30-second tool timeout by default. No redirects, automatic retries or ambient proxy credentials are used.

The generic conformance suite includes controlled context responses and a wire-level process fixture. It validates envelope identity, follow-up context and citations reaching the transcript. Those are test fixtures, not a live DataFusion result. Before acceptance, test your real endpoint for: correct user scope; forbidden source rejection; empty results; source versions/citations; oversized/invalid output; unavailable service; prompt injection in source text; and credential revocation. Keep external write operations separate from context search and give them independent approval/receipt contracts.

## Structured rows and document excerpts

The shipped example now accepts an optional `kind`, structured `rows` and bounded scalar `metadata` on each source. Each source still requires its reference, version and textual explanation. For example:

```json
{"sources":[
  {"reference":"datafusion://assets/A17","version":"v3","kind":"structured","text":"A17 has 8 pumps.","rows":[{"asset_id":"A17","pump_count":8}]},
  {"reference":"datafusion://manuals/A17","version":"rev7","kind":"document","text":"Inspect pumps every 90 days.","metadata":{"page":4}}
]}
```

DataFusion owns SQL/query planning, indexing, document parsing and source authorization. The harness owns user/tool permission checks, delegated credentials, argument/result validation, bounded execution and trace. This contract does not restrict your eventual API: adapt or replace the reviewed schema deliberately.

## Opt-in connector probe

Once a real connection is configured, use the shipped probe without starting a model or provisioning harness storage:

```sh
pandita-agent-context-probe --config config/agent.json \
  --token-file /private/runtime/user.jwt --agent assistant \
  --tool datafusion_search --arguments-file /private/runtime/query.json
```

The arguments file contains `{"query":"A17 pumps and maintenance interval"}`. The user JWT must authenticate against the configured identity provider and have agent/session/tool access. The connection's token file is a separate delegated DataFusion credential. Only configured read-only REST/MCP tools are accepted. The probe issues one request without retries and emits a response digest and source count, not source text or credentials. Exit status is nonzero on authentication, permission, transport or schema failure. An empty successful response stays explicitly empty. A passing contract probe does not establish model quality or prove authorization inside DataFusion.

`tests/test_context_kit.py` exercises the authenticated Python SDK → API → worker loop → real local HTTP adapter using synthetic database rows and document excerpts, followed by a second user question. Additional cases cover permission rejection, empty output, malformed/oversized results, timeout and refusing to probe a write tool. The source fixture contains hostile text to check that transport does not turn data into a granted capability; this deterministic test is not model prompt-injection qualification. No customer DataFusion service or live model is used by this kit.
